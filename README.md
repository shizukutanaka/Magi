# Magi

タロットに特化した、完全無料のWebアプリケーションです。
ログイン不要・DBなしで、決定的なタロットのドメイン層と参照用APIを提供します。

> **方針変更（タロット特化）**: Magi はかつて9つの占術（タロット・易経・ルーン・おみくじ・西洋占星術・数秘術・干支／四柱推命・マヤ暦ツォルキン・ジオマンシー）と、複数の占術を並べる「今日の三賢者」を備えた総合占いアプリでした。現在はタロット専用です。
> タロット以外の8占術と「今日の三賢者」は削除したため、**それらの共有URL（`engine=iching` などタロット以外の `engine` を持つもの、および `daily=1` のもの）は動作しません**。これは方針変更の意図した帰結です。Web UI では対応していない旨を表示し、API は `404`、`python -m app.verify` は終了コード `2` を返します。
> **タロットの共有URLは従来どおり動作します。** 同じ入力・同じシードなら、変更前と完全に同じ結果を返します（`backend/tests/test_tarot_golden.py` で変更前の出力と照合しています）。

## 方針

- タロットの全スプレッド（スリーカード・ケルト十字）を無条件で利用できます。
- 生年月日・氏名・問いは鑑定計算にのみ使用し、サーバに保存せず、ログにも出力しません。
- 濫用防止のため、鑑定APIにはIPアドレス単位のインメモリ・レートリミットだけを設けています。
- レートリミットの既定値は1分あたり60リクエストです。`MAGI_RATE_LIMIT_PER_MINUTE` で変更でき、0以下にすると無効になります。整数として解釈できない値は、変数名を示すエラーを出して起動を停止します。
- レートリミットの状態はプロセス内のメモリにだけ持ちます。`--workers` を増やしたり、同じ設定のコンテナを複数並べたりすると、上限は実質そのプロセス数の倍になります。既定のDockerfileとREADMEの起動コマンドは1プロセスです。再起動するとカウントは失われます。
- 前段プロキシの `X-Forwarded-For` は既定で信頼しません。信頼できるプロキシの背後で運用する場合のみ `MAGI_TRUST_PROXY=1` を設定してください。`MAGI_TRUST_PROXY` は `1`・`true`・`yes`・`on` または `0`・`false`・`no`・`off` を受け付け、それ以外は変数名を示すエラーを出して起動を停止します。既定の起動コマンドでは Uvicorn の `--proxy-headers` も切っています。
- 入力の長さには上限があります（問い200字・氏名100字・subject key とオプション64字）。超過時は 422 を返します。

## 技術スタック

- **Backend**: Python 3.12 / FastAPI / Pydantic v2
- **品質管理**: pytest / ruff
- **設計**: DB・ネットワーク・保存状態に依存しないステートレスなタロットエンジン

## タロットの仕組み

- **デッキ**: ライダー・ウェイト・スミス版の78枚（大アルカナ22枚・小アルカナ56枚）。各カードに正位置・逆位置それぞれのキーワードと解釈本文を持ちます。
- **スプレッド**: `options.spread` で選びます。
  - `three-card`（既定）: 過去・現在・未来の3枚。
  - `celtic-cross`: 現状・課題・過去・近い未来・意識・無意識・自分・環境・願望・結論の10枚。
- **引き方**: シードから決まる乱数で、デッキから重複なくスプレッドの枚数を引き、1枚ごとに正位置・逆位置を決めます。
- **解釈**: 各ポジションに、引いたカードの正位置／逆位置の本文を対応させます。問いを入力した場合は、問いの領域に合わせた「問いについて」のセクションを1つ加え、最後に全体の指針を添えます。

同じブラウザで同じ対象日・問い・入力を使えば、`generated_at` を除いて同じ結果を返します。
レスポンスには計算に使った `seed` が含まれるため、同じ入力を用意すれば結果の再現性を検証できます。

### 何を簡略化しているか

Magiはタロットの機構を意図的に軽量化しています。何を省いているかを隠さないために列挙します。

- **シャッフルとカット**: 物理的なシャッフル・カット・山分けは再現せず、シードから決まる乱数でデッキから重複なく抜き取ります。
- **正位置・逆位置**: 1枚ごとに等確率（1/2）で決めます。カードを回転させる混ぜ方や、逆位置を採らない流儀は扱いません。
- **スプレッド**: スリーカードとケルト十字の2種類だけです。ケルト十字のポジション名と順序は流派によって異なりますが、Magiは上記の1通りに固定しています。
- **解釈本文**: 伝統的に広く共有されているカードの象意に沿って独自に著述したものです。カード同士の組み合わせ（隣接するカード、スートや数の偏り）は読みません。
- **スコア**: タロットには伝統的な吉凶の格付けがないため、スコアは付けません（APIの `score` は常に `null`）。

## 起動

```bash
cd backend
uv venv
source .venv/bin/activate
uv pip install -r requirements.txt
uvicorn app.main:app --reload --no-proxy-headers
```

起動後は `GET /health`、`GET /api/v1/systems`（タロット1件だけを返します）、
`POST /api/v1/readings`（`engine_id` は `tarot`）を利用できます。鑑定APIにはIPレートリミットが適用されますが、
`/health` には適用されません。

## Web UI

`uvicorn app.main:app` を起動した後、ブラウザで
`http://localhost:8000/` を開くと、トップがそのままタロットの鑑定画面になり、鑑定と履歴を利用できます。
UIはHTML・CSS・ES Modulesだけで構成されており、ビルド工程、npm、`node_modules` は必要ありません。
フロントエンドも同じFastAPIプロセスから配信されるため、self-hostの起動方法は変わりません。

履歴はブラウザのlocalStorageにのみ保存され、画面からJSONとしてエクスポートまたは全削除できます。
サーバは履歴を含むリクエストデータを保存しません。

### タロット専用ページ（単体アプリ）

タロットだけをすぐに占える単一ファイルのページを `frontend/tarot.html` に同梱しています。
起動後に `http://localhost:8000/tarot.html` を開くと、APIを使わずそのページだけで
ライダー・ウェイト版78枚の「今日の一枚」と3枚引き（過去・現在・未来）が利用できます。
日本語／英語の切替に対応し、履歴はブラウザのlocalStorageにのみ保存されます。
カードの解釈データはバックエンドの正本（`backend/app/divination/data/`）と同一の内容で、
その一致（78枚の並び・名前・キーワード・正逆の解釈、ja/en）は `backend/tests/test_data_integrity.py` が検査します。
データの完全性は `frontend/tests/tarot.test.mjs` で検証できます。

### 共有URL

共有URLの再現用ペイロードはURLフラグメント（`#` 以降）に載せるため、サーバや
アクセスログには届きません。`s` にはブラウザ識別子ではなく、その鑑定専用のトークンを
載せます。同じブラウザから作った異なる鑑定のリンクは異なるトークンになるため、
リンク同士をブラウザ単位で結び付けられません。以前の `?` 形式のタロットの共有URLもそのまま
再現できます。タロット以外の占術や「今日の三賢者」の共有URLは、方針変更により再現できません
（冒頭の注記を参照）。Magiを開いたままのタブで共有URLを開いた場合は、アプリを再読み込みして
その鑑定を再現します。

鑑定リクエスト自体では、結果の計算に使う問いをPOSTボディでサーバへ送りますが、
サーバには保存しません。

### 問いは結果に反映されます

問いを入力すると、その問いをキーワードから決定的に7領域（恋愛・仕事・金銭・健康・
人間関係・決断・全般）へ分類し、「問いについて（領域）」というセクションを総合の
直後に1つ追加します。分類はLLMを使わず入力だけから決まるため、同じ問いなら常に
同じ領域になります。日本語と英語で同じ辞書を使うので、表示言語を変えても領域は
変わりません。問いを空にした場合はこのセクションは追加されません。

### 多言語対応

表示言語は日本語（`ja`）と英語（`en`）に対応しています。言語は
`?lang=`、`Accept-Language`、日本語の順で決まり、画面の切り替えは表示だけを
変更します。言語はシードに含まれないため、同じ入力と subject key なら言語を
変えても同じ結果を再現できます。

タロットの解釈本文は日本語と英語で書かれています（機械翻訳ではなく、原文と
同じ長さ・語り口で書き直したものです）。APIは `interpretation_langs`
として解釈本文の提供言語を申告し、訳が無い言語で表示した場合は画面に
その旨を明示してフォールバックします。新しい表示言語を追加する場合は、
`backend/app/i18n/` にカタログファイルを1つ追加し、`SUPPORTED_LANGS` と
`CATALOGS` のタプル・辞書へ1件登録します。解釈本文も訳す場合は
`backend/app/divination/data/<lang>/` に安定IDをキーにしたテキストを追加します
（日本語データが唯一のソースで、訳は別ロケール層に置きます）。

### 自分で結果を再現する

APIレスポンスの `seed` は、subject key・占術ID（`tarot`）・対象日・問い・入力（スプレッドなど）から決まります。
レスポンスの入力と `seed` を記録し、同じコードを自分の環境で実行することで、決定的な結果を検証できます。

```bash
cd backend
source .venv/bin/activate
uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers
```

`MAGI_STATIC_DIR` を設定すると、フロントエンドを配信するディレクトリを差し替えられます（既定はリポジトリの `frontend/`、Dockerイメージでは `/app/frontend`）。明示的に指定したディレクトリが存在しない場合は設定エラーを出して起動を停止します。既定の `frontend/` が見つからない場合だけ、静的配信をマウントせずAPI-onlyで起動します。
起動時には、読み込んだ実効設定をINFOレベルで1行ログに出します。外部でlogging設定が無い場合はMagiがstderrへINFOハンドラを自前で追加し、既存のlogging設定がある場合はそれを上書きしません。

## self-host（Docker）

Dockerがあれば、リポジトリのルートで次の2コマンドだけで起動できます。

```bash
docker build -t magi .
docker run --rm -p 8000:8000 magi
```

起動後に <http://localhost:8000/> を開いてください。データベースや別の
バッキングサービスは必要ありません。

公開イメージ（GHCR）を使う場合は、リポジトリ同梱の `docker-compose.yml` で
そのまま起動できます。

```bash
docker compose pull
docker compose up -d
```

ソースからビルドする場合は `docker compose up -d --build` としてください。
ポートは `MAGI_PORT`、版は `MAGI_VERSION`（例: `MAGI_VERSION=1.2.3`）で
変えられます。サーバは状態を持たないため永続ボリュームは不要で、
鑑定履歴は利用者のブラウザにだけ残ります。

## デスクトップ版（補助ランチャー）

Magi の正規の形態は「利用者が自分の環境で動かすソフトウェア」です。上の self-host（GHCR の公開イメージ＋`docker-compose.yml`）で起動してください。
`desktop/` にあるデスクトップ版は、その補助ランチャーにすぎません。Magi 本体（Python のサーバとタロットのエンジン）は含まれておらず、
利用者が自分で起動した Magi を専用ウィンドウで開くだけです。デスクトップ版だけでは占えません。
ランチャーは占術に依存しないため、タロット特化に伴う変更はありません。

- 接続先の既定は `http://localhost:8000` です。メニューの「接続 → 接続先を変更…」で変更でき、OS のユーザーデータ領域（`launcher.json`）に保存されます。接続先は http(s) のオリジン（スキーム・ホスト・ポート）だけを受け付けます。
- 起動時に接続先の `/health` へ疎通確認し、`{"status":"ok"}` が返らない場合は、理由（接続拒否・タイムアウト・名前解決の失敗・Magi 以外の応答など）と compose での起動手順を示す画面を表示します。開いている途中で Magi が停止した場合も同じ画面に戻ります。
- ウィンドウは `contextIsolation` 有効・`nodeIntegration` 無効・`sandbox` 有効・preload なしで動きます。新しいウィンドウは開かず、接続先以外への遷移とリダイレクトは遮断します。http/https のリンクは OS の既定ブラウザで開きます。
- 鑑定履歴は、ブラウザ版と同じく接続先オリジンごとの localStorage に保存されます。接続先を変えると別の履歴になります。

配布物は Windows が portable（`.exe`）、macOS が `.zip`、Linux が AppImage です。
**いずれもコード署名・公証をしていません。** Windows では SmartScreen、macOS では Gatekeeper の警告が出る場合があります。
不安がある場合はデスクトップ版を使わず、ブラウザで `http://localhost:8000/` を開いてください。機能は同じです。

ソースから起動・ビルドする場合（Node.js 22 以降）:

```bash
cd desktop
npm ci
npm start          # 開発用に起動
npm test           # 接続先の検証・遷移判定・/health 判定の単体テスト
npm run dist       # 実行中の OS 向けの配布物を desktop/dist/ に作成
```

`electron` と `electron-builder` は版数を固定し、`desktop/package-lock.json` で依存関係を固定しています。

## セキュリティヘッダ

Magiは静的ファイルだけでなくAPIとエラーレスポンスにも、
`Content-Security-Policy`、`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、
`Referrer-Policy: no-referrer` を付けます。CSPの `default-src 'self'` により、
アプリは第三者のリソースを読み込まないため、外向きのネットワーク接続なしで動作します。

Swagger UIをCDNから読み込むインタラクティブな `/docs` と `/redoc` は無効にしています。
OpenAPIスキーマは `/openapi.json` で取得できるため、必要な場合はローカルのビューアで
表示できます。

## 鑑定を検証する

共有URLを受け取った人は、サーバ・ネットワーク・アカウントなしで、同じ鑑定を
手元で再現できます。バックエンドディレクトリで次を実行してください。

```bash
cd backend
source .venv/bin/activate
python -m app.verify '<共有URL>' --expect-seed <seed>
```

`seed` が共有URLの鑑定結果と一致するかを確認できます。

## テスト

```bash
cd backend
uv venv
source .venv/bin/activate
uv pip install -r requirements.txt pytest httpx ruff
python -m ruff check app tests
python -m pytest -q
```

フロントエンドのテストは Node.js で実行します（`npm` は不要です）。

```bash
cd frontend
for test in tests/*.test.mjs; do node "$test"; done
```

`frontend/tests/share.test.mjs` は、タロットの共有URLの形式が変更前と同一であることを確認します。

デスクトップ用ランチャー（`desktop/`）の単体テストは `cd desktop && npm ci && npm test` で実行できます。

開発への参加方法は [CONTRIBUTING.md](CONTRIBUTING.md) を参照してください。

## CI

GitHub Actions のワークフロー `.github/workflows/backend-ci.yml` が push / pull_request ごとに
Ruff・pytest・共有URLのオフライン検証CLI・フロントの構文検査と単体テスト（翻訳・履歴ストア・結果カード・タロット）を実行します。
`ci/backend-ci.yml` は同じ内容の写しです。変更するときは両方を揃えてください。
